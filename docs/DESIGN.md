# hsig — оффлайн-синтезатор на Haskell

Рабочее имя `hsig`, переименовать по вкусу.

Этот документ — вход для агента. Работать по этапам из раздела «Дорожная карта»;
каждый этап заканчивается зелёными тестами из раздела «Приёмочные проверки».
Разделы «Ключевые решения» и «Антипаттерны» — не рекомендации, а ограничения:
если реализация им противоречит, неправа реализация.

---

## 1. Цель

Библиотека и DSL на чистом Haskell для **оффлайнового** синтеза электронной музыки.
Трек описывается текстом как обычный хаскелльный код, рендерится в WAV.

Целевой звук — плотный сатурированный электро в духе Vitalic: расстроенные пилы
через резонансный лестничный фильтр с быстрой огибающей, дисторшн после фильтра,
слоистые голоса, ритмическое гейтирование.

**Приоритеты, в порядке убывания:**

1. Качество звука. Алиасинг и артефакты недопустимы, даже ценой стократного
   замедления рендера.
2. Эргономика комбинаторов. Трек должен декомпозироваться на изолированные
   модули, каждый из которых читается отдельно.
3. Скорость рендера. Последний по важности пункт. Не оптимизировать, пока
   рендер минуты музыки укладывается в минуты.

**Не цели:** реалтайм, GUI, плагинные форматы, MIDI-вход, кроссплатформенность
сверх Linux/macOS.

## 2. Ключевые решения

Эти решения приняты осознанно и отменяют «очевидные» альтернативы.

**Сигнал — это буфер, а не потоковый автомат.** Оффлайн-рендер снимает
необходимость в инкрементальной модели. Никаких `Arrow`, `SF`, FRP, Reflex,
Yampa, `conduit`/`streamly` в публичном API. Процессор — обычная функция
`Sig -> Sig`, композиция — обычная `(.)` / `(>>>)` / `(&)`.

**Рекурсия по сэмплам инкапсулирована в примитивах.** Фильтры, гребёнки,
компрессоры пишутся внутри `runST` с `MVector`. Наружу торчит `Fx`.
Пользовательский код рекурсию не видит.

**Все параметры — `Sig`, не `Double`.** Инстанс `Num` даёт литералы, поэтому
`ladder 2000 0.85` и `ladder (200 + 5200*e) 0.85` типизируются одинаково.
Модулировать можно всё; отдельного «модуляционного» слоя нет.

**Осцилляторы аддитивные, не аппроксимированные.** Никакого naive saw,
никакого PolyBLEP. Суммируем гармоники до Найквиста. Это дорого и это
единственный вариант, дающий математически точный результат.

**Оверсэмплинг — комбинатор, а не глобальная настройка.** `oversample :: Int -> Fx -> Fx`
поднимает частоту дискретизации локально для поддерева графа.

**Партитура и DSP — два независимых слоя.** Инструмент это `Note -> Sig`,
партитура — отдельная алгебра паттернов. Они не знают друг о друге.

## 3. Ядро: типы

```haskell
-- Sound/Sig/Core.hs

data Env = Env
  { envRate   :: !Double  -- текущая частота дискретизации (меняется в oversample)
  , envBlock  :: !Int     -- размер блока в сэмплах, по умолчанию 4096
  , envSeed   :: !Int     -- база для детерминированного шума
  , envMaxSec :: !Double  -- потолок длины стема и мастера, страховка от
  } deriving (Eq, Ord, Show) -- забытого окна (разд. 8), по умолчанию 600

type Chunks = [U.Vector Double]     -- ленивый список блоков; конечный или бесконечный

newtype Sig = Sig { runSig :: Env -> Chunks }

type Fx = Sig -> Sig
```

Инвариант: все блоки, кроме последнего, имеют длину `envBlock`. Последний может
быть короче. Пустых блоков быть не должно.

### Инстансы

`Num`, `Fractional`, `Floating` поэлементно. **Семантика длин различается по
операциям и это важно:**

- `(+)`, `(-)` — дополняют более короткий сигнал нулями до длины более длинного.
  Иначе микс ломается.
- `(*)`, `(/)` — обрезают до длины более короткого. Благодаря этому огибающая
  задаёт длительность ноты: `osc f * adsr ...` конечен.
- `fromInteger`, `fromRational` — бесконечная константа.

Реализовать через один комбинатор `zipChunks :: PadMode -> (Double -> Double -> Double) -> Sig -> Sig -> Sig`,
где `data PadMode = PadZero | Truncate`.

### Разделение вычислений

`Sig` — это функция от `Env`, поэтому `x + x` вычислит `x` дважды. Для графа с
переиспользованием узлов это экспоненциальный взрыв. Решение:

```haskell
share :: Sig -> Sig
```

Реализация — `unsafePerformIO` + `IORef (Map Env Chunks)`, ограниченный
несколькими записями (разные `Env` возникают только из-за вложенных
`oversample`). Модуль `Core` помечен `{-# NOINLINE #-}` на нужных местах.

**Правило для всего кода патчей:** любой `Sig`, использующийся в определении
больше одного раза, оборачивается в `share`. Написать про это в хаддоке и
добавить в CI линт-проверку не получится — просто соблюдать.

Альтернатива, если `unsafePerformIO` окажется неприемлемым: строить граф в
билдер-монаде с явным `let`. Не начинать с неё — сложнее эргономически.

## 5. API ядра

Сигнатуры, к которым нужно прийти. Имена можно менять, форму — нет.

```haskell
-- Osc
phase   :: Sig -> Sig              -- частота -> накопленная фаза (радианы), интеграл
sine    :: Sig -> Sig
saw     :: Sig -> Sig
square  :: Sig -> Sig              -- позже: pulse :: Sig -> Sig -> Sig (ширина)
tri     :: Sig -> Sig
noise   :: Int -> Sig              -- детерминированный по seed

-- Envelope
line    :: [(Double, Double)] -> Sig          -- линейные брейкпоинты (время, значение)
expseg  :: [(Double, Double)] -> Sig          -- экспоненциальные сегменты
adsr    :: Double -> Double -> Double -> Double -> Double -> Sig  -- a d s r dur
expdecay:: Double -> Sig                      -- мгновенная атака, экспоненциальный спад

-- Filter
onepole :: Sig -> Fx                          -- TPT, cutoff
ladder  :: Sig -> Sig -> Fx                   -- cutoff, resonance 0..1
svf     :: Sig -> Sig -> Fx

-- Nonlin
shaper  :: Sig -> Fx                          -- drive -> tanh(drive*x)/tanh(drive)
cubicnl :: Sig -> Sig -> Fx                   -- drive, смещение (асимметрия)
clip    :: Double -> Fx
decimate:: Int -> Int -> Fx                   -- редукция битов, редукция частоты

-- Resample
oversample :: Int -> Fx -> Fx
resample   :: Double -> Sig -> Sig            -- смена частоты дискретизации

-- Delay
delay   :: Double -> Fx                       -- фиксированная задержка в секундах
comb    :: Double -> Sig -> Fx                -- время, фидбэк
allpass :: Double -> Sig -> Fx

-- Dynamics
compress  :: Double -> Double -> Double -> Double -> Fx   -- thresh ratio attack release
sidechain :: Sig -> Double -> Fx                          -- управляющий сигнал, глубина
```

Утилиты композиции берём из `base`: `(&)` из `Data.Function`, `(>>>)` из
`Control.Category`. Своих операторов не изобретать.

## 6. Требования к DSP

Это самая содержательная часть. Каждый пункт влияет на то, будет ли звучать
как плагин или как студенческая лаба.

### 6.1 Фазовый интегратор

Частота — сигнал, поэтому фаза считается накоплением:
`φ[n] = φ[n-1] + 2π·f[n]/sr`, с приведением по модулю `2π` для сохранения
точности `Double` на длинных нотах.

### 6.2 Аддитивные осцилляторы

Пила: `saw φ = (2/π) · Σ_{k=1..K} (-1)^(k+1) · sin(k·φ) / k`
Меандр: `square φ = (4/π) · Σ_{k нечётные} sin(k·φ) / k`
где `K = floor(nyquist / f)`.

**Критично:** при свипе частоты `K` меняется, и гармоники, выпадающие за
Найквист, дают щелчки. Каждая гармоника умножается на плавный коэффициент,
спадающий от 1 до 0 на верхней части диапазона — например, raised cosine на
последней октаве до Найквиста. Проверяется тестом на свипе.

Стоимость: при 40 Гц и 48 кГц это 600 синусов на сэмпл. Это нормально.
Оптимизация через рекуррентное вычисление `sin(kφ)` из `sin((k-1)φ)`
накапливает ошибку — не использовать, считать честно или через таблицу с
интерполяцией высокого порядка. Мипмапнутые вейвтейблы — возможная оптимизация
на потом, не в первой версии.

### 6.3 Лестничный фильтр

Топология Zavalishin TPT (zero-delay feedback), четыре однополюсника
последовательно, обратная связь `k = 4·res`, **нелинейность `tanh` в петле
обратной связи** — именно она даёт компрессирующийся резонанс вместо
цифрового визга.

Однополюсник TPT:
```
g = tan(π·fc/sr)
G = g/(1+g)
v = (x - s)·G;  y = v + s;  s' = y + v
```

Нелинейная петля решается итеративно: `u_{i+1} = x - k·tanh(L(u_i))`, где `L` —
цепочка из четырёх звеньев, вычисленная с **замороженным** состоянием.
Четыре итерации фиксированной точки. Состояние коммитится только после
сходимости. Это ключевой момент — если состояние мутировать внутри итераций,
фильтр развалится.

Компенсация падения громкости при росте резонанса — опционально, по вкусу.

### 6.4 Ресемплинг и оверсэмплинг

FIR проектируется методом оконного sinc с окном Кайзера, β подбирается под
затухание ≥ 120 дБ в полосе задерживания. Длина порядка `64·L` отводов.
Реализация полифазная.

`oversample n fx`:
1. интерполяция входа в `n` раз;
2. `fx` выполняется с `envRate * fromIntegral n` и `envBlock * n`;
3. децимация обратно.

**Компенсация задержки обязательна.** FIR линейнофазовый, задержка `(N-1)/2`
отводов на каждой стадии. Без компенсации параллельные ветви графа разъедутся
и в миксе появится гребёнчатая фильтрация. Задержка компенсируется внутри
`oversample`, наружу он должен быть прозрачным по времени — это проверяется
null-тестом.

### 6.5 Выход

Внутри всё в `Double`. При записи WAV: опционально 32-битный float без
изменений, либо 24/16 бит с TPDF-дизером. Клиппинг фиксируется в лог с
указанием времени, не подавляется молча.

## 7. Слой партитуры

```haskell
data Note = Note
  { noteOnset :: !Double            -- секунды от начала стема
  , noteDur   :: !Double
  , noteFreq  :: !Double
  , noteAmp   :: !Double
  , noteLabel :: !String            -- слово из паттерна: по нему барабаны
  }                                 -- выбирают голос, мелодия его игнорирует

type Instrument = Note -> Sig       -- сигнал начинается с t=0, длина конечна
```

Алгебра паттернов — семантика Tidal: `Pattern a` это функция из временного
отрезка в список событий, с честными `Functor`/`Applicative`/`Monad`.

**На первом этапе не тянуть пакет `tidal` как зависимость** — он тащит `hosc`,
`network` и реалтайм-обвязку, которые не нужны. Вместо этого реализовать
минимальное ядро (`Arc`, `Event`, `queryArc`, `pure`, `fmap`, `<*>`, `stack`,
`cat`, `fast`, `slow`, `every`, `rev`, `degradeBy`) — это порядка 200 строк.
Семантику брать из Tidal один в один, чтобы потом можно было мигрировать.
Мини-нотация строками — опционально и в последнюю очередь.

Планировщик: для каждого события инструмент рендерит конечный `Sig`, результат
складывается overlap-add в буфер стема со смещением `round (onset * rate)`.
Ноты независимы, поэтому здесь естественно ложится `parMap` — но только после
того, как всё заработает.

## 8. Рендер и стемы

```haskell
data Stem = Stem
  { stemName  :: String
  , stemSig   :: Sig
  , stemPan   :: Double        -- -1 слева, 0 по центру, 1 справа
  , stemCache :: Maybe String  -- спецификация, если кэш включён
  }

stem       :: String -> Sig -> Stem      -- по центру, без кэша
cached     :: String -> Stem -> Stem
panned     :: Double -> Stem -> Stem
stereoStem :: String -> Stereo -> [Stem]

renderStem :: Env -> FilePath -> Stem -> IO FilePath
mixStems   :: Env -> [FilePath] -> IO Sig
```

Каждый стем рендерится в отдельный файл на диске, микс собирается из файлов.
Причина: ленивый список блоков, использованный дважды, удерживается целиком —
пять минут при 384 кГц это порядка гигабайта на канал. Плюс это даёт итерацию
над одним стемом без пересчёта остальных.

Кэш: ключ - хэш от спецификации стема плюс `Env` (`envSeed`, `envRate`), имя
файла `out/<stem>-<hash>.wav`. По умолчанию кэш выключен: стем без него пишется
в `out/<stem>.wav` и считается заново каждый прогон. Причина - `Sig` это
функция, сериализовать её нечем, спецификацию пишет руками автор трека, и
забытая правка строки даёт старый звук молча. Включать кэш имеет смысл там, где
рендер долгий, и явно (`cached`). Длина стема в ключ не входит: её задаёт
материал, узнать её заранее нельзя, поэтому длину описывает та же строка.

Уборка оставляет несколько последних версий каждого стема, а не одну: рабочий
цикл это метание между вариантами (превью на восемь секунд и полный прогон),
и снос всего, кроме текущего, отменял бы кэш ровно там, где он нужен.

Стем обязан кончаться сам, поэтому забытое окно ловится потолком `envMaxSec`
(по умолчанию 600 с) - и для стема, и для мастера, которому обработка при
сведении тоже может добавить бесконечный хвост. Трек честно длиннее - потолок
поднимают в `Env`.

## 9. Приёмочный патч

Цепочка, воспроизводящая целевой тембр. Служит финальной проверкой того, что
все компоненты работают вместе.

Порядок обработки, отклонения от которого меняют звук качественно:

1. **Питч-огибающая** — спад на квинту за 30 мс, экспоненциальный.
2. **Unison** — 7 пил, расстройка ±18 центов, у каждой независимый дрейф
   (синус 0.05–0.15 Гц, глубина ~1 цент). Без дрейфа стек звучит статично.
3. **Лестничный фильтр** — резонанс 0.85, катофф `200 + 5200·expdecay 0.09`.
4. **Дисторшн строго после фильтра.** Это главное решение всей цепочки:
   гармоники нелинейности рождаются вокруг резонансного пика и едут вместе с
   ним при свипе. Обратный порядок даёт жирный, но мёртвый звук.
5. Пункты 3–4 целиком завёрнуты в `oversample 8`.
6. **Гребёнка** 11 мс с фидбэком 0.6 — металлический призвук.
7. **Амплитудная огибающая.**
8. Параллельный слой с `decimate` подмешивается на ~20%.

```haskell
-- patches/Lead.hs
lead :: Instrument
lead n = unison 7 18 (freq * pEnv)
       & oversample 8 (ladder cut 0.85 >>> cubicnl 0.9 0.15)
       & comb 0.011 0.6
       & (* aEnv)
  where
    freq = constant (noteFreq n)
    pEnv = 1 + 0.5 * expdecay 0.03
    cut  = 200 + 5200 * expdecay 0.09
    aEnv = adsr 0.002 0.4 0.6 0.1 (noteDur n)
```

## 10. Целевая эргономика

Так выглядит файл трека. Это критерий приёмки для API: если получилось не так -
API неправильный, а не пример. Рабочий вариант целиком: `tracks/Demo.hs`.

```haskell
-- tracks/Demo.hs
module Demo (main) where

import Sound.Sig
import Lead (leadWide)

-- Такт это два цикла: четыре доли в цикле дают 120 ударов в минуту. Темп
-- задаёт паттерн, отдельного поля под него нет.
bar :: Pattern a -> Pattern a
bar = slow 2

trackSec :: Double
trackSec = 32

-- Паттерн бесконечен, а длина трека берётся из материала: значит стем
-- обязан кончиться сам. Окно на весь трек и есть его длина.
window :: Sig
window = gate 0.01 trackSec

-- Шина стема: накачка от бочки, окно и уровень в миксе.
bus :: Sig -> Fx
bus level sig = sidechain kickSig 0.7 sig * window * level

track :: [Stem]
track =
  [ stem "kick" (kickSig * window)
  , stem "bass" (bus 2 (play bassInst (bar (every 4 (fast 2) "a1 ~ a1 c2"))))
  , panned 0.35 (stem "hat" (bus 1.5 (play hatInst (bar (degradeBy 0.25 "hh*8")))))
  ]
    -- Кэш выключен по умолчанию и включается там, где рендер долгий: версия в
    -- строке двигается вместе с правкой патча, длина входит в неё же.
    <> map (cached ("лид v1, " <> show trackSec <> " с")) (stereoStems "lead" leadOut)

kickSig :: Sig
kickSig = share (play kickInst (bar "a1*4"))

leadOut :: Stereo
leadOut = bothChannels (bus 1.2) (playStereo leadWide (bar "a4 c5 ~ e5"))

-- Мастер идёт после сведения, поэтому его правка не сбивает кэш стемов.
master :: Stereo -> Stereo
master = bothChannels (shaper 1.2 >>> (* 0.9))

main :: IO ()
main = renderTrackWith defaultEnv "out/track.wav" master track >>= putStrLn
```

Что из этого следует для API:

- стем это имя плюс сигнал (`stem`), панорама и кэш - опции поверх
  (`panned`, `cached`), а не поля, которые надо заполнять;
- ритм и ноты пишутся строками: `"a1 ~ a1 c2"` это `Pattern Note`, имена нот
  переводятся в герцы (`OverloadedStrings` включён в стансе трека);
- длина трека не аргумент рендера, а свойство материала: аргументом её пришлось
  бы повторять в каждом вызове и держать согласованной с окном;
- готовое стерео (`orbit`, широкий унисон) кладётся в микс как `stereoStem`, а
  не расписывается по каналам руками;
- обработка мастера отдельным аргументом (`renderTrackWith`), потому что она
  идёт после сведения и её правка не должна сбивать кэш стемов.

## 11. Дорожная карта

Каждый этап — рабочий коммит с зелёными тестами. Не переходить дальше, пока
предыдущий не закрыт.

**M0 — скелет.** Cabal-проект, flake.nix, `Env`/`Sig`/`Chunks`, инстансы `Num`
с обеими семантиками длин, `share`, запись WAV. Критерий: `cabal run demo`
пишет двухсекундную синусоиду 440 Гц, слышно чистый тон.

**M1 — осцилляторы.** Фазовый интегратор, аддитивные saw/square/tri, шум.
Критерий: тест на алиасинг проходит.

**M2 — огибающие.** Брейкпоинты, adsr, expdecay. Конечность сигналов через
умножение. Критерий: нота с огибающей имеет ровно ожидаемую длину, тишины и
щелчков на краях нет.

**M3 — фильтр.** TPT-однополюсник, ZDF-ладдер с итеративным решением и `tanh`
в фидбэке. Критерий: АЧХ при `res=0` совпадает с аналитическим 4-полюсным ФНЧ;
при `res=0.99` фильтр самовозбуждается и не расходится.

**M4 — ресемплинг.** Проектирование FIR, полифазная реализация, `oversample` с
компенсацией задержки. Критерий: null-тест.

**M5 — нелинейности и задержки.** Шейперы, клиппер, децимация, comb, allpass.
Критерий: `oversample 8 (shaper 5)` на синусе 3 кГц даёт продукты алиасинга
ниже −90 dBFS, без оверсэмплинга — заметно выше (проверка, что комбинатор
реально работает).

**M6 — партитура.** Ядро `Pattern`, `Note`, `Instrument`, overlap-add
планировщик, рендер стемов на диск. Критерий: демо из четырёх нот собирается
из паттерна и звучит ритмично.

**M7 — приёмка.** Патч из раздела 9, демо-трек на 16 тактов. Критерий:
субъективный — звучит плотно и без грязи.

**M8 — опционально.** Кэш по хэшу, параллельный рендер нот, мини-нотация
строками, стерео.

**M9 — движение по кругу.** `vdelay`: задержка с изменяемым временем и
дробным чтением (округление до сэмпла даёт щелчки на движущемся источнике).
Ядро — оконный sinc на 16 отводов: у дешёвой кубической интерполяции
ослабление зависит от дробной части (на полусэмпле −3.25 дБ на 16 кГц), и на
движущемся источнике это дрожание верха. Цена — минимальная задержка в
половину ядра, 8 сэмплов; фленджер сквозь ноль этим примитивом не собрать.
Замер ядра: до 12 кГц ослабление не измеряется, на 16 кГц −0.007 дБ, на
18 кГц −0.226, на 20 кГц −1.47.
`orbit`: сферическая модель головы — межушная задержка до 0.65 мс, теневой
фильтр дальнего уха, умеренная разница уровней. Патч-реактор из трёх
пульсирующих стержней.

Неочевидное про раскладку стержней. Одновременно звучит ровно один стержень
(при трёх стержнях в пике вспышки соседи по фазе дают минус 72 дБ), поэтому
слышно не сумму точек, а последовательность вспышек. Инвариант: за период
вспышки набор точек продвигается ровно на `orbitHz / pulseHz` оборота при
любом разносе, а сам разнос лишь раскладывает n вспышек внутри периода.
При `spread = 0` они лежат равномерно, шаг между соседними
`orbitHz / (n * pulseHz)`, луч ровным шагом обходит голову — это и нужно.
При `spread = orbitHz / (n * pulseHz)` все n схлопываются в одну точку:
обход остаётся, но втрое грубее. При `spread = 1/n` (стержни поровну по
кругу, что выглядит правильнее всего) вспышки разбросаны по кругу и порядок
обхода перемешан — на слух это разброс, а не вращение, и замер подтверждает:
качание баланса на частоте оборота падает более чем вчетверо.

Критерий: на 90 градусах межушная разница 0.65 мс с верным знаком, на 45 —
0.46 мс; у дальнего уха энергия выше 4 кГц впятеро меньше; по кругу
суммарная энергия не проваливается; вращение не даёт разрывов; в мастере
качание баланса на частоте оборота держит основную часть всей модуляции
образа.

**M10 — HRTF.** Настоящая бинауральная свёртка вместо параметрической
модели. Состав:

- набор измеренных характеристик (MIT KEMAR, 44.1 кГц, компактный по 128
  отводов) тянется в flake с фиксированным хэшем и читается нашим `readWav`;
  формат SOFA не берём, он тянет NetCDF/HDF5;
- пересчёт характеристик в частоту рендера полифазным ресемплером из M4;
- разложение каждой характеристики на чистую задержку и минимально-фазовую
  часть: задержку отыгрывает `vdelay`, спектральную часть — FIR;
- интерполяция между соседними направлениями по этим двум частям порознь.
  Кроссфейд самих характеристик не годится, на движении он даёт гребёнку;
- свёртка с обновлением фильтра по блокам.

Открытые вопросы: FFT в библиотеке (сейчас `vector-fftw` только в тестах)
либо предпосчёт минимальной фазы в данные; лицензия набора и его вес в
репозитории. Более дешёвая замена, если данные окажутся неудобны, —
структурная модель Брауна-Дуды: к сферической голове из M9 добавляются
отражения ушной раковины (несколько коротких задержек, зависящих от
направления) и отражение от плеч около 0.25 мс; спектральные зарубки от них
дают какое-то различение перед-зад без всяких данных.

Чего этап не решает: неиндивидуальные характеристики у заметной доли
слушателей оставляют путаницу перед-зад (лечится поворотом головы, которого
в офлайн-рендере нет), а на колонках нужна ещё компенсация перекрёстных
наводок, зависящая от расстановки. То есть результат — наушниковый формат.

Критерий: на направлении из сетки отклик совпадает с эталонной
характеристикой с точностью до ресемплинга; между направлениями межушная
задержка меняется монотонно; движущийся источник не даёт разрывов; спектр
дальнего уха несёт зарубку раковины, которой нет у ближнего.

**M11 — богатство партитуры.** Довести набор комбинаторов до уровня Tidal.
Этап не разовый, а фоновый: партии делаются по мере надобности, и каждый
комбинатор приезжает сразу с тремя вещами - хаддок, тест с зубами (рисунок
ритма или значений, а не «не падает») и хотя бы одно появление в книге со
звуком. Семантика везде списывается с Tidal, чтобы чужие рецепты переносились
дословно.

Порядок партий по музыкальной пользе:

1. Структура и наложение (сделано): `appLeft`, `struct`, `segment`, `euclid`,
   `euclidInv`, `superimpose`, `off`, `sometimesBy` с семейством,
   `undegradeBy`, `ply`, `iter`, `palindrome`, `whenmod`.
2. Мини-нотация (сделано): `!` (повтор), `@` (вес доли), `(k,n,rot)` прямо
   в строке, полиметр `{a b, c d e}%n`, `.` как быстрая группировка,
   диапазоны `0 .. 3`. Осталось: аккорды в строке и паттерны в аргументах
   евклида.
3. Время и выбор: сделаны `within`, `inside`, `swingBy` и `playWhen` (свинг
   понадобился даунтемпо, глава 16). Осталось: `linger`, `trunc`, `chunk`,
   `rot`, `run`, `someCyclesBy`, `randcat`, `wchoose`, `shuffle`, `scramble`.
4. Высоты: лады (`scale`), арпеджиатор (`arp`), разбор аккордов в строке.
5. Паттерны параметров. В Tidal параметр патча патчится так же, как ноты
   (`# cutoff "400 800"`). У нас параметры это `Sig`, поэтому нужен мост
   «паттерн значений - сигнал»: это отдельное дизайн-решение, а не
   механическая работа, и делать его надо после того, как станет ясно, чего
   не хватает на практике.

Не делаем принципиально: живое кодирование, OSC, MIDI, переходы между
паттернами на лету. Это инструменты исполнения, а проект про изготовление
(разд. 1).

## 12. Приёмочные проверки

Тесты на `tasty` (`tasty-hunit` + `tasty-quickcheck`). Спектральный анализ
через `vector-fftw`.

**Алиасинг.** Свип пилы 20 Гц → 8 кГц за 4 секунды при 48 кГц. Для каждого
кадра БПФ: энергия в бинах, не совпадающих с гармониками мгновенной частоты
(с допуском ±2 бина), должна быть ниже −100 dBFS относительно фундаментальной.

**Отклик фильтра.** Белый шум через `ladder fc 0`, усреднённый спектр
сравнивается с `|H(f)| = 1/(1+(f/fc)²)²` — отклонение не более 0.2 дБ до
`0.45·sr`.

**Прозрачность оверсэмплинга.** `oversample 8 id` против `id` на розовом шуме:
разность ниже −140 dBFS в полосе до `0.4·nyquist`.

**Ресемплер.** Неравномерность в полосе пропускания < 0.01 дБ, затухание в
полосе задерживания < −120 дБ.

**Свойства ядра (QuickCheck).** Коммутативность и ассоциативность `(+)` на
конечных сигналах; `x * 1 == x`; `x + 0 == x` с сохранением длины; длина
`a * b` равна минимуму длин; длина `a + b` равна максимуму.

**Детерминизм.** Два рендера одного трека дают побитово идентичные файлы.

## 13. Антипаттерны

Не делать, даже если кажется, что так лучше:

- Не вводить `Arrow`, `SF`, FRP, Reflex, Yampa в публичный API. Рекурсия по
  сэмплам живёт только внутри примитивов.
- Не использовать naive band-unlimited осцилляторы «пока для теста». Они
  просочатся в патчи и испортят звук незаметно.
- Не делать GUI, веб-интерфейс, превью в браузере.
- Не оптимизировать до M7. Скорость — последний приоритет.
- Не делать параметры типа `Double` там, где может быть `Sig`.
- Не тащить `lens`, `mtl`, эффект-системы. `base` + `vector` покрывают всё.
- Не глотать клиппинг молча.
- Не использовать `Data.Vector` (boxed). Только `Data.Vector.Unboxed`.
- Не делать глобальное изменяемое состояние, кроме кэша в `share`.
- Не изобретать свою семантику паттернов. Копировать Tidal.

## 14. Окружение

`flake.nix` с `haskellPackages`, GHC свежий стабильный. Зависимости:

- `vector`, `primitive` — буферы и `ST`
- `vector-fftw` — только для тестов и проектирования FIR
- `WAVE` или `hsndfile` — ввод-вывод
- `containers`, `deepseq`
- `directory`, `filepath`, `temporary`, `time` - файлы стемов и кэш (разд. 8)
- `tasty`, `tasty-hunit`, `tasty-quickcheck`
- `criterion` — опционально, после M7

Флаги: `-O2 -fllvm` (если доступно), `-funbox-strict-fields`. Все поля записей
строгие. `INLINE` на мелких поэлементных функциях в горячем пути.

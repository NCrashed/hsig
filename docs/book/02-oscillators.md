# Глава 2. Осцилляторы и алиасинг

## Наивная пила и что с ней не так

Самый очевидный способ сделать пилу - взять фазу и растянуть её в отрезок
от -1 до 1. `phase` как раз отдаёт накопленную фазу в радианах, приведённую
к `[0, 2*pi)`:

```haskell file=book/Book/Ch02.hs sym=naiveSaw
naiveSaw :: Sig -> Sig
naiveSaw f = mapSig (\p -> p / pi - 1) (phase f)
```

Три строки, и звучит как пила. Проблема в том, что идеальная пила содержит
бесконечно много гармоник, а частота дискретизации конечна. Всё, что выше
Найквиста, не исчезает - оно отражается вниз и попадает в слышимый диапазон
на частотах, не кратных основному тону. Это алиасинг, и на слух он
опознаётся мгновенно: при движении ноты вверх часть призвуков едет вниз.

Проверим глиссандо от 200 Гц до 4 кГц:

```haskell file=book/Book/Ch02.hs sym=sweep
sweep :: (Sig -> Sig) -> Sig
sweep osc = osc (200 * exp (line [(0, 0), (5, log 20)])) * 0.2 * gate 0.01 5
```

Частота здесь тоже сигнал: `line` строит линейные брейкпоинты, `exp` от него
даёт экспоненциальный, то есть равномерный по восприятию, подъём. Так
работает любой параметр - модулировать можно всё.

Послушайте подряд:

- [`out/book/02-saw-naive.wav`](../../out/book/02-saw-naive.wav) - призраки,
  ползущие вниз навстречу основному тону, и металлический призвук ближе к
  концу;
- [`out/book/02-saw-additive.wav`](../../out/book/02-saw-additive.wav) - тот
  же глиссандо честной пилой.

## Аддитивный синтез

`saw` из библиотеки не приближает пилу, а складывает её из гармоник, пока
они помещаются под Найквистом:

```
saw(f) = (2/pi) * sum_{k=1..K} sin(k * phase) / k,  K = floor(rate / (2*f))
```

Верхняя гармоника гасится плавно (raised cosine), иначе её появление и
исчезновение при движении частоты было бы слышно как щелчок. Цена - счёт
пропорционален числу гармоник: бас на 55 Гц это 436 синусов на каждый сэмпл.
По приоритетам проекта (разд. 1 дизайна) это правильный обмен: качество
звука важнее скорости рендера.

Так же устроены `square`, `tri` и `pulse`. Никакого PolyBLEP, никаких
таблиц.

```haskell file=book/Book/Ch02.hs sym=shapes
shapes :: Sig
shapes = mix [delay (fromIntegral i) (voice o) | (i, o) <- zip [0 :: Int ..] waves]
  where
    waves = [saw, square, tri, pulse 0.15]
    voice o = o 110 * 0.2 * gate 0.01 0.9
```

`delay t` сдвигает сигнал на `t` секунд, а сумма их выстраивает подряд:
отдельного секвенсора для этого не нужно, достаточно семантики `(+)`.
Слушайте [`out/book/02-shapes.wav`](../../out/book/02-shapes.wav): пила,
меандр, треугольник, узкий импульс. Треугольник заметно тише прочих - у него
гармоники спадают как 1/k^2, и это правда про волну, а не про реализацию.

## Ширина импульса

У `pulse` ширина это отдельный сигнальный аргумент, поэтому её можно
крутить прямо во время звучания:

```haskell file=book/Book/Ch02.hs sym=pulses
pulses :: Sig
pulses = pulse width 110 * 0.2 * gate 0.01 4
  where
    width = 0.5 + 0.45 * sine 0.5
```

Это классический PWM: [`out/book/02-pwm.wav`](../../out/book/02-pwm.wav).
Тембр дышит от меандра до тонкого жужжания, потому что чётные гармоники то
появляются, то исчезают.

Одно предупреждение про уровень. `pulse w` сделан как разность двух пил и
даёт уровни `2 - 2w` и `-2w`, то есть при узком импульсе пик доходит до 2, а
не до 1. Умножайте на что-то меньше 0.5, если ширина уезжает в края.

## Шум

`noise seed` это белый шум, детерминированный по номеру сэмпла: один и тот
же seed даёт один и тот же шум при любом размере блока и при любом числе
прогонов. Без этого рендер перестал бы быть воспроизводимым, а сравнивать
две версии трека можно только если всё, кроме правки, побитово совпадает.

Красить шум будем фильтрами в главе 4.

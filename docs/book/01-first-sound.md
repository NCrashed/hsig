# Глава 1. Первый звук

## Сигнал это функция, а не буфер

`Sig` не хранит сэмплы. Это функция от окружения рендера к ленивому списку
блоков:

```haskell file=src/Sound/Sig/Core.hs sym=Sig
newtype Sig = Sig {runSig :: Env -> Chunks}
```

Отсюда два следствия, которые определяют всё дальнейшее. Первое: пока никто
не попросил сэмплы, ничего не считается, поэтому сигнал может быть
бесконечным. Второе: частота дискретизации не зашита в сигнал, её приносит
`Env` в момент рендера, и поэтому `oversample` умеет считать поддерево графа
на другой частоте (глава 5).

Окружение по умолчанию это 48 кГц, блок 4096 сэмплов, нулевой seed:

```
> defaultEnv
Env {envRate = 48000.0, envBlock = 4096, envSeed = 0, envMaxSec = 600.0}
```

## Тон

Синус на 440 Гц бесконечен. Чтобы получился файл, ему нужна длина, а чтобы
не щёлкнуло на краях - гашение. И то и другое даёт `gate edge dur`:

```haskell file=book/Book/Ch01.hs sym=tone
tone :: Sig
tone = sine 440 * 0.3 * gate 0.01 2
```

Здесь работают сразу три вещи.

Число `440` это `Sig`: у сигналов есть `Num`, и литерал разворачивается в
бесконечную константу. Поэтому частоту можно не только задать числом, но и
промодулировать чем угодно - `sine (440 + 30 * sine 5)` это вибрато, и
никакого отдельного слоя модуляции для этого не нужно.

Умножение на `0.3` это громкость. Полная шкала это 1.0, и запас нужен
всегда: складывать сигналы вы будете позже, а [клиппинг](glossary.md#clipping) слышен сразу.

Умножение на `gate 0.01 2` задаёт длину. Это ключевой момент: `(*)` обрезает
результат по более короткому аргументу, поэтому огибающая и есть длительность.
Сложение, наоборот, дополняет короткий сигнал нулями до длинного, иначе микс
терял бы хвосты. Две операции с разной семантикой длин - осознанное решение
(разд. 3 дизайна), и на нём стоит вся эргономика: нота кончается сама, а сумма
нот не обрезается по самой короткой.

Запись в файл:

```
> writeWav defaultEnv Bits16 "out/tone.wav" tone
```

Послушайте: [`out/book/01-tone.wav`](../../out/book/01-tone.wav).

## Почему края обязательны

Тот же тон, но обрезанный по времени без гашения:

```haskell file=book/Book/Ch01.hs sym=clicky
clicky :: Sig
clicky = takeSec 2 (sine 440 * 0.3)
```

Послушайте [`out/book/01-click.wav`](../../out/book/01-click.wav): в конце
отчётливый щелчок. Обрыв синуса посреди периода это скачок амплитуды, а
скачок это широкий спектр. Библиотека не подмешивает фейд молча: гашение
краёв это решение автора, а не поведение по умолчанию, потому что иногда
резкий край нужен.

`takeSec` полезен для проб и для страховки, но длину музыкального материала
почти всегда задаёт огибающая, а не он.

## Складываем

Аккорд это сумма трёх голосов разной длины:

```haskell file=book/Book/Ch01.hs sym=chord
chord :: Sig
chord = mix [voice f d | (f, d) <- [(220, 2), (277.18, 1.4), (330, 0.8)]]
  where
    voice f d = sine (constant f) * 0.2 * gate 0.01 d
```

`constant f` нужен потому, что `f` это `Double` из списка, а не литерал:
литерал компилятор сам развернёт в `Sig`, обычное значение - нет.

Голоса гаснут в разное время, и сумма длиной с самый длинный: это та самая
семантика `(+)`. Послушайте
[`out/book/01-chord.wav`](../../out/book/01-chord.wav).

Обратите внимание на уровень: три голоса по 0.2 в пике дадут 0.6, и это
нормально. Считать запас по пикам придётся всегда, автоматической нормировки
в библиотеке нет - она превратила бы динамику трека в кашу.
